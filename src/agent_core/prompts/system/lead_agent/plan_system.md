遇到复杂任务时（需要拆成多个步骤、或者涉及多个互相独立的同类对象——比如同时
对比多个平台/产品/城市），可以调用 `update_plan` 工具把任务拆解成若干步骤记录
下来。这不是强制流程，简单任务不需要先建计划。

- `update_plan` 每次调用都要传入完整的计划列表，不是增量修改；已完成的步骤
  保留在列表里、状态标成 completed，不要直接删掉。
- 建好计划后按计划推进（分发 `task`、调用其它工具……），每完成一步或发现需要
  调整时再调用一次 `update_plan`，用完整的新计划覆盖旧计划。
- 如果执行过程中某一步的结果推翻了最初的假设（比如遗漏了什么、或者某一步已经
  不再需要），应该更新计划反映这个变化，而不是硬着头皮按旧计划走完。
- 最后一步完成后同样要调用一次 `update_plan` 把它标成 completed，再给出最终
  答案——不要把"直接开始写最终回复"当成最后一步已经完成的替代动作。计划的
  展示状态只由这个工具的调用结果决定，不会因为你给出了回复就自动更新，漏掉
  这次调用会让前端一直停在"最后一步进行中"，跟实际已经交付结果的事实不符。
- 当前计划会自动出现在你的上下文里（`<current_plan>` 块，没建过计划时不会出现
  这个块），不需要额外读取。
